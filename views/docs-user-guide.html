User Guide_

The Intelligence Dashboard is your real-time command center for autonomous threat monitoring. This guide covers every panel, how the engine processes threats, and how enforcement actions are applied.

Open Dashboard →

1. Dashboard Layout & Navigation

After logging in at intelligence.cybat.co, you land on the main Intelligence Dashboard. The navigation sidebar provides access to all core platform features based on your assigned role: Dashboard, Investigations, Data Ingestion, Users (Admin), Whitelist (Admin), API Keys (Admin), and Webhooks.

Metric Cards

Five cards at the top of the dashboard show your organisation's security posture at a glance: Data Ingested, Threats Blocked, High Severity, Medium Severity, and Low Severity. All figures reflect the selected time period (Day / Month / Year).

3D Threat Globe

A rotating Earth visualization showing the geographic origin of all detected threats. Red points represent origins with high-severity incidents; amber points represent medium-severity. Click any point to open a breakdown by severity, then click View incidents → to filter the Investigations feed to that location.

Investigations Feed

A live list of all detected threats sorted by recency. Each row shows source IP, threat level, target URL, timestamp, and enforcement verdict. Click any row to open the full incident detail panel. Use the 👍 / 👎 buttons to provide feedback — thumbs down on a blocked IP opens an unblock confirmation dialog.

Incident Detail Panel

Opens over the feed. Shows the full Gemini AI analysis narrative, all telemetry evidence records that triggered the detection, the enforcement decision and status, and the notification dispatched to your team. Admins can unblock an IP directly from this panel using the 👎 feedback button.

2. How the Engine Processes a Threat

HTTP telemetry streamed by the Cybat SDK moves through the following pipeline automatically. The entire sequence completes in under 5 seconds from request capture to enforcement.

01
Ingestion — The Cybat SDK, installed as middleware in your app, streams captured request telemetry to API Gateway, which validates your API key at the edge and forwards accepted batches through Pub/Sub to the SOC agent.
02
IP Grouping — Requests from the same telemetry batch are grouped by source IP to build a per-IP request picture before analysis.
03
Subscription Check — The engine validates your organization's active Marketplace subscription via GCP Service Control before proceeding.
04
Whitelist Filter — IPs present in your organisation's whitelist are removed from the batch entirely. No analysis, no incident record, no cost. Traffic from trusted IPs is completely ignored by the engine.
05
Verdict Cache — IPs seen in the last 24 hours skip Gemini re-analysis and are enforced immediately using the cached verdict, eliminating redundant AI calls.
06
Gemini Analysis — New IPs are analyzed by Vertex AI Gemini 2.5 Flash Lite. The model receives the full request context (headers, path, method, client metadata) and returns a structured verdict: threat level (high / medium / low / none) and a human-readable explanation.
07
Enforcement — For high and medium verdicts, the engine attempts VPC Firewall deny first (Layer 3/4), falling back to Cloud Armor IP block (Layer 7) when the network can't be discovered. Enforcement targets the GCP project you configured via gcpProjectId on the SDK — without it, the engine detects and alerts but never modifies infrastructure.
08
Persistence & Alerting — The incident, AI analysis, and evidence records are written to the dashboard. An alert notification is dispatched to your configured webhooks with the full threat summary and enforcement outcome.

4. Feedback & Manual Unblock

Every incident in the feed and detail panel has 👍 / 👎 feedback buttons. Feedback trains the system's false-positive rate reporting and helps your team audit enforcement decisions.

Thumbs Up — Correct Classification

Marks the incident as a true positive. The feedback is recorded and counted in your monthly signal-to-noise report.

Thumbs Down on a Detected (not blocked) Incident

Marks the incident as a false positive. The feedback is recorded immediately.

Thumbs Down on a Blocked Incident — Admin Only

A confirmation dialog appears asking whether to remove the active block. Clicking Yes, unblock immediately removes the Cloud Armor or VPC Firewall rule for that IP and marks the incident expired. The feedback is also saved as a false positive. Clicking No, keep blocked saves only the feedback without touching the enforcement rule.

Note: unblocking is scoped to your organisation only and requires the Admin role. The action is logged with the email of the admin who performed it.

5. IP Whitelist

The Whitelist menu item (visible to admins only) lets you register trusted IP addresses that the engine should never analyze or block — for example, your office network, a monitoring service, or a known partner API.

How it works

  • Whitelisted IPs are filtered out of every telemetry batch before the AI analysis step — no Vertex AI call is made, no incident is created, and no usage is counted for those requests.
  • Whitelisted IPs are also exempt from enforcement: even if a cached verdict exists for the IP, no block will be applied.
  • The whitelist is scoped to your organisation. Each org manages its own list independently.

Managing the whitelist

  • Navigate to Whitelist in the left sidebar (admin role required).
  • Enter an IPv4 or IPv6 address and an optional note explaining why it is trusted, then click Add IP.
  • To remove an entry, click Remove in the corresponding row. The change takes effect on the next telemetry batch.

Tip: if an IP is currently blocked and you also want to whitelist it, unblock it first using the 👎 feedback dialog, then add it to the whitelist to prevent future blocks.

6. Data Ingestion & Quota Monitoring

The Data Ingestion view provides real-time visibility into the volume of HTTP traffic streamed from your applications via the Cybat SDK, alongside your monthly plan consumption.

Plan Quota Tracker

A live status bar displays your current consumption against your Google Cloud Marketplace subscription quota (e.g., Total / Quota requests and percentage used). Color-coded indicators notify you as your organization approaches monthly plan limits.

Time Period & Historical Navigation

Filter ingestion telemetry by Day, Month, or Year. Use the previous (‹) and next (›) controls to audit historical traffic patterns and confirm active SDK telemetry across all services.

7. API Key Management

The API Keys view (Admin only) allows you to provision, inspect, and revoke credentials used by the Cybat SDK to stream events securely to the ingestion gateway.

Creating & Storing API Keys

  • Click Create API Key, assign a descriptive label (e.g., prod-api-cluster), and optionally set an expiration date.
  • One-time reveal: The secret key is displayed only once upon generation. Copy and store it securely (e.g., in Google Secret Manager or as CYBAT_API_KEY). It cannot be retrieved again.

Edge Validation & Instant Revocation

  • Every request sent by the SDK is validated by GCP API Gateway at the network edge before reaching Cybat compute infrastructure.
  • If a key is compromised or a service is decommissioned, click Revoke. The key is instantly blocked at the edge with zero caching delay.

8. Webhooks & Alert Integrations

The Webhooks view enables automated event dispatch to your security operations tooling, SIEM/SOAR platforms, PagerDuty, or chat channels whenever a threat is classified.

Configuring an HTTPS Webhook

  • Navigate to Webhooks and click Add Webhook.
  • Specify a name and your HTTPS destination URL (e.g., a webhook receiver, incident response endpoint, or Slack incoming webhook).
  • Select which event severities trigger the webhook: High (critical mitigations), Medium (flagged threats), and/or Low (anomalies).

Authentication & Payloads

  • Configure custom webhook authentication headers, such as Bearer tokens or static API keys, to verify authenticity on your receiving server.
  • Dispatched JSON payloads include source IP, geographic coordinates, Gemini AI analysis narrative, enforcement action taken (VPC Firewall / Cloud Armor), and affected GCP project ID.

9. User Management & Role-Based Access

The Users view (Admin only) allows organization administrators to invite team members and manage role-based permissions.

Google Identity Single Sign-On (SSO)

Platform access is gated by Google Identity SSO. When inviting team members, provide their Google Workspace email address. Users sign in seamlessly without separate password management.

Roles & Permissions

Role Capabilities
Admin Full platform access: manage team members, generate/revoke API keys, configure webhooks, add/remove IP whitelists, and perform manual IP unblocks.
User Security analyst access: monitor dashboard metric cards, explore 3D Threat Globe, inspect investigations and incident details, and submit classification feedback.

Revoking Access

Admins can remove team members at any time by clicking Remove next to their entry. Revocation takes effect immediately, terminating active portal access.
