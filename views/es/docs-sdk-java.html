Referencia del SDK de Java_

Un jakarta.servlet.Filter estándar para Spring Boot 3+ y contenedores Jakarta Servlet 5.0+ (Tomcat 10+, Jetty 11+) que reporta el tráfico HTTP directamente al Motor de Inteligencia Cybat con cero dependencias en tiempo de ejecución.

● DISPONIBLE AHORA co.cybat:cybat-sdk en Maven Central Java 17+ Jakarta Servlet 5.0+ Cero dependencias de runtime

SDKs por Lenguaje Disponibles

Python (PyPI) Node.js (npm) PHP (Packagist) Java (Maven Central) Go — próximamente

Inicio Rápido_

Cuatro pasos desde la configuración de dependencias hasta la protección autónoma activa ante amenazas.

1.

Añade la dependencia

Disponible directamente en Maven Central para Maven o Gradle:

<dependency>
    <groupId>co.cybat</groupId>
    <artifactId>cybat-sdk</artifactId>
    <version>1.0.0</version>
</dependency>
2.

Crea una clave de API

Desde el Portal de Inteligencia → API Keys. Guárdala como una variable de entorno o secreto llamada CYBAT_API_KEY.

3.

Registra el bean CybatFilter

En Spring Boot 3+, registra un FilterRegistrationBean<CybatFilter> con la máxima precedencia — consulta los Ejemplos de Frameworks a continuación.

4.

Genera tráfico y observa el panel

El tráfico aparece en el Portal de Inteligencia en segundos: el servicio se muestra como Connected, el Globo de Amenazas rastrea activamente los orígenes IP y los incidentes se reportan en tiempo real.

Instalación_

Instala mediante tu herramienta de compilación preferida. Requiere Java 17+ y apunta a jakarta.servlet (Servlet 5.0+ / Jakarta EE 9+).

Apache Maven

Añade a tu pom.xml:

<dependency>
    <groupId>co.cybat</groupId>
    <artifactId>cybat-sdk</artifactId>
    <version>1.0.0</version>
</dependency>

Gradle

Añade a tu build.gradle:

implementation 'co.cybat:cybat-sdk:1.0.0'
Cero Dependencias en Tiempo de Ejecución

El SDK de Java se apoya exclusivamente en java.net.http.HttpClient (integrado en JDK 11+) y un analizador JSON propio libre de dependencias. Evita bibliotecas JSON externas (Jackson, Gson, org.json), eliminando colisiones en el classpath con las dependencias de la aplicación anfitriona. La dependencia jakarta.servlet-api está marcada como <scope>provided</scope> y la proporciona tu contenedor.

Ejemplos de Código en Frameworks_

Fragmentos de configuración listos para incorporar en Spring Boot 3+ y contenedores Jakarta Servlet estándar.

Spring Boot 3+ (Spring MVC)

Registra un FilterRegistrationBean en tu clase de configuración. Definir Ordered.HIGHEST_PRECEDENCE asegura que Cybat instrumente todas las peticiones entrantes antes de los interceptores del controlador:

package com.example.demo.config;

import co.cybat.sdk.CybatFilter;
import co.cybat.sdk.Options;
import org.springframework.boot.web.servlet.FilterRegistrationBean;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.Ordered;

@Configuration
public class CybatConfig {

    @Bean
    public FilterRegistrationBean<CybatFilter> cybatFilter() {
        Options options = Options.builder(System.getenv("CYBAT_API_KEY"))
            .gcpProjectId("mi-proyecto-gcp") // habilita el bloqueo automatizado en Cloud Armor / VPC Firewall
            .serviceName("checkout-service")
            .captureBody(true)
            .build();

        CybatFilter filter = new CybatFilter(options);

        FilterRegistrationBean<CybatFilter> registration = new FilterRegistrationBean<>(filter);
        registration.addUrlPatterns("/*");
        registration.setOrder(Ordered.HIGHEST_PRECEDENCE);
        return registration;
    }
}

Contenedor Jakarta Servlet Estándar (Tomcat 10+, Jetty 11+)

Regístralo programáticamente en un ServletContextListener o inicializador de servlet:

import co.cybat.sdk.CybatFilter;
import co.cybat.sdk.Options;
import jakarta.servlet.FilterRegistration;
import jakarta.servlet.ServletContext;
import jakarta.servlet.ServletContextEvent;
import jakarta.servlet.ServletContextListener;
import jakarta.servlet.annotation.WebListener;

@WebListener
public class CybatInitializer implements ServletContextListener {

    @Override
    public void contextInitialized(ServletContextEvent sce) {
        ServletContext ctx = sce.getServletContext();

        Options options = Options.builder(System.getenv("CYBAT_API_KEY"))
            .gcpProjectId("mi-proyecto-gcp")
            .serviceName("legacy-api")
            .build();

        CybatFilter filter = new CybatFilter(options);
        FilterRegistration.Dynamic reg = ctx.addFilter("cybatFilter", filter);
        reg.addMappingForUrlPatterns(null, false, "/*");
    }
}
¿Detrás de un balanceador de carga o proxy inverso?

CybatFilter lee la IP del cliente a través de request.getRemoteAddr(). Cuando se despliega tras un balanceador de carga, proxy inverso o Cloud CDN, asegúrate de que tu contenedor servlet esté configurado para analizar los encabezados de reenvío (por ejemplo, RemoteIpValve en Tomcat o server.forward-headers-strategy=native en Spring) para que se reporte la IP real del cliente y no la del proxy.

Mitigación Automática con Cloud Armor y VPC Firewall

Configurar gcpProjectId activa la clasificación y alertas en tiempo real de inmediato. Para permitir que Cybat bloquee de forma autónoma IPs maliciosas detectadas mediante reglas de Cloud Armor y VPC Firewall, otorga a la Cuenta de Servicio de Cybat los roles roles/compute.securityAdmin y roles/compute.networkViewer en tu proyecto de GCP de destino.

Enrutamiento Multi-Cloud_

Define exactamente uno entre gcpProjectId o awsProjectId en el constructor de opciones (requerido, nunca ambos en la misma instancia). El valor configurado determina a dónde se enrutan los datos automáticamente.

Parámetro configurado Destino de los datos Estado
gcpProjectId("...") gcp-ingest.cybat.co Activo
awsProjectId("...") aws-ingest.cybat.co Próximamente

Una aplicación desplegada en ambos proveedores cloud debe registrar dos instancias separadas de CybatFilter. Configurar ambas propiedades en un mismo Options.Builder lanzará una IllegalArgumentException en tiempo de compilación.

Referencia de Configuración_

Construido mediante el patrón fluent builder de tipado seguro Options.builder(apiKey).

Opción Tipo Predeterminado Descripción
apiKey String Obligatorio Clave de API generada desde el Portal de Inteligencia → API Keys.
gcpProjectId String null Obligatorio a menos que se defina awsProjectId. Enruta al ingest de GCP y habilita la mitigación automatizada con Cloud Armor / VPC Firewall.
awsProjectId String null Enruta al endpoint de ingest en AWS (próximamente).
serviceName String null Identificador opcional mostrado en las líneas de tiempo de incidentes y eventos de telemetría.
ingestUrl String auto Sobrescribe la URL cloud de destino (principalmente para pruebas con mocks locales).
flushIntervalMs long 2000 Intervalo en milisegundos entre envíos asíncronos en segundo plano de eventos en búfer.
maxBatchSize int 100 Dispara un envío inmediato en segundo plano cuando la cola en memoria alcanza este tamaño.
maxRetries int 2 Número máximo de reintentos con retroceso exponencial antes de descartar un lote fallido.
retryBackoffMs long 500 Demora base para reintentos; se duplica exponencialmente en intentos sucesivos.
statusFilter StatusFilter StatusFilter.ALL Filtro de predicado (StatusFilter.ALL, StatusFilter.ERRORS, o lambda personalizada status -> status != 304).
captureBody boolean false Habilita la redacción en proceso y captura de telemetría de cuerpos de peticiones.
bodyMaxBytes int 2048 Tamaño máximo en bytes del extracto del cuerpo tras la redacción (límite de 8192).
bodyStatusFilter StatusFilter null Captura cuerpos de peticiones solo cuando el estado de la respuesta coincide con este predicado.
extraSensitiveKeys Collection<String> null Nombres de campos adicionales a enmascarar durante la redacción en proceso (ej. Set.of("numero_cuenta", "ultimos_4_ssn")).

Cuerpos de Petición y Redacción_

captureBody está desactivado de manera predeterminada. Habilitar la captura de cuerpos proporciona al Motor de Inteligencia indicadores de ataque esenciales (SQLi, inyección de comandos, relleno de credenciales, prompt injection), manteniendo estrictas garantías de privacidad:

1.
Enmascaramiento en proceso de fuga cero: Antes de que los eventos abandonen la memoria, las cargas útiles se analizan y enmascaran localmente. Correos electrónicos, tarjetas de crédito con checksum de Luhn válido, tokens Bearer/JWT, claves de API y campos confidenciales (password, token, cvv, ssn) se redactan de forma permanente.
2.
Preservación de la estructura del ataque: Los valores confidenciales se reemplazan por descriptores estructurales neutrales como [REDACTED len=14 sus=quote,comment]. Los patrones maliciosos siguen siendo perceptibles para los modelos de amenazas sin exponer secretos de usuarios.
3.
Envoltura de peticiones de doble flujo: CybatFilter envuelve la petición entrante para interceptar tanto getInputStream() como getReader() de manera segura. Solo se capturan los cuerpos leídos efectivamente por el código de la aplicación, limitados por un búfer máximo en tránsito de 1 MiB. Los flujos binarios y multipart se omiten por completo.
4.
Enmascaramiento de campos confidenciales personalizados: Amplía la redacción con tus propios campos específicos del dominio mediante extraSensitiveKeys. La coincidencia de campos es exacta e insensible a mayúsculas para evitar enmascaramientos accidentales.
Options options = Options.builder(System.getenv("CYBAT_API_KEY"))
    .gcpProjectId("mi-proyecto-gcp")
    .captureBody(true)
    .bodyMaxBytes(4096)
    .extraSensitiveKeys(java.util.Set.of("numero_cuenta", "ultimos_4_ssn", "expediente_medico_id"))
    .build();
