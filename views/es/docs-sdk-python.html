Referencia SDK Python_

Middleware para Flask, Django, FastAPI y cualquier aplicación ASGI que reporta el tráfico HTTP directamente a Cybat Intelligence Engine.

● DISPONIBLE AHORA cybat-sdk en PyPI Python 3.9+ Cero dependencias en tiempo de ejecución

SDKs Disponibles por Lenguaje

Python (PyPI) Node.js (npm) PHP (Packagist) Java (Maven Central) Go — próximamente

Inicio Rápido_

Cuatro pasos desde una terminal vacía hasta la detección en vivo.

1.

Instalar el paquete

pip install cybat-sdk
2.

Crear una clave API

Desde el Portal de Inteligencia → API Keys. Se muestra solo una vez: guárdela como CYBAT_API_KEY, no se puede volver a consultar.

3.

Agregar el middleware

Una importación y una llamada; consulte los Ejemplos de Código a continuación para su framework.

4.

Generar tráfico y monitorear el panel

Las peticiones aparecen en el Portal de Inteligencia en segundos: app listada como Conectada, Threat Globe poblándose e incidentes en el feed.

Instalación_

pip install cybat-sdk

Versiones compatibles de Python

3.9, 3.10, 3.11, 3.12, 3.13

Dependencias

Ninguna en ejecución: el SDK utiliza únicamente urllib de la biblioteca estándar para sus llamadas HTTP.

Ejemplos de Código_

Las tres integraciones aceptan las mismas opciones; consulte la Referencia de Configuración para ver la lista completa.

Flask

WSGI 
from flask import Flask
from cybat_sdk.integrations.flask import init_app

app = Flask(__name__)
init_app(app,
    api_key=os.environ["CYBAT_API_KEY"],
    gcp_project_id="my-gcp-project",  # requerido (o aws_project_id); también habilita el bloqueo automático
    service_name="checkout-api",      # opcional, solo una etiqueta en incidentes
)

Django

Middleware WSGI 
# settings.py
MIDDLEWARE = [
    # ... otros middleware ...
    "cybat_sdk.integrations.django.CybatMiddleware",
]
CYBAT_API_KEY = os.environ["CYBAT_API_KEY"]
CYBAT_GCP_PROJECT_ID = "my-gcp-project"  # requerido (o CYBAT_AWS_PROJECT_ID); también habilita el bloqueo automático

Cada opción tiene un equivalente CYBAT_* en la configuración: el nombre en Django es CYBAT_ seguido del nombre de la opción en mayúsculas.

FastAPI / Starlette

ASGI 
from cybat_sdk.integrations.asgi import CybatASGIMiddleware

app.add_middleware(CybatASGIMiddleware,
    api_key=os.environ["CYBAT_API_KEY"],
    gcp_project_id="my-gcp-project",
)

Implementa directamente el protocolo ASGI puro, permitiendo que las respuestas en streaming funcionen sin alteraciones. Para una app ASGI sin add_middleware: app = CybatASGIMiddleware(app, api_key=...).

¿Detrás de un balanceador de carga o proxy inverso?

Configure el mecanismo habitual de su framework para confiar en X-Forwarded-For (p. ej. ProxyFix de Werkzeug en Flask); de lo contrario, cada solicitud reportará la IP de su proxy en lugar de la del cliente real.

Enrutamiento Multinube_

Configure exactamente uno de gcp_project_id o aws_project_id: es obligatorio y nunca deben usarse ambos simultáneamente en la misma instancia del SDK.

Configuración Destino de datos Estado
gcp_project_id gcp-ingest.cybat.co Activo
aws_project_id aws-ingest.cybat.co Aún no implementado

Una aplicación que se ejecuta en ambas nubes requiere dos instancias del SDK, una por nube, nunca una única instancia con ambos campos configurados.

Referencia de Configuración_

Flask y ASGI los aceptan como argumentos con nombre; Django los lee desde settings.py como CYBAT_*.

Opción Por Defecto Descripción
api_key — Requerido. Clave sin procesar del Portal de Inteligencia.
gcp_project_id — Requerido a menos que se defina aws_project_id. Enruta a GCP y habilita bloqueo automático.
aws_project_id — Requerido a menos que se defina gcp_project_id. Enruta a AWS (próximamente).
service_name None Etiqueta opcional mostrada en incidentes.
ingest_url auto Invalida la detección automática en la nube: útil para pruebas locales o staging.
flush_interval_ms 2000 Frecuencia con la que se descarga un lote parcial en milisegundos.
max_batch_size 100 Descarga inmediatamente una vez que el búfer alcanza este tamaño.
max_retries 2 Reintentos antes de descartar un lote fallido (3 intentos en total).
retry_backoff_ms 500 Retraso base antes del primer reintento; se duplica en cada reintento.
status_filter "all" "all" | "errors" | un callable (status: int) -> bool.
capture_body False Envía un extracto redactado del cuerpo de la petición.
body_max_bytes 2048 Límite en bytes para el extracto del cuerpo tras la redacción (máx. 8192).
body_status_filter "all" Captura cuerpos solo para respuestas coincidentes, independiente de status_filter.
extra_sensitive_keys None Nombres de campo adicionales redactados como la lista integrada (coincidencia exacta sin distinguir mayúsculas): p. ej. {"account_number"}.

Cuerpos de Petición y Redacción_

capture_body está desactivado por defecto. Los cuerpos son donde se manifiestan los ataques de inyección, el credential stuffing y la inyección de prompts, por lo que habilitarlo mejora significativamente la detección:

1.
La redacción es automática. Antes de almacenar un evento en búfer, el cuerpo se enmascara en el proceso local: correos, números de tarjeta (verificados por Luhn), tokens JWT/Bearer, claves de proveedores y campos como password, token, cvv, ssn.
2.
Un secreto enmascarado conserva la estructura del ataque, no su valor. Se reemplaza por un descriptor sin contenido como [REDACTED len=13 sus=quote,comment], permitiendo que una inyección SQL dentro de un campo de contraseña siga siendo visible para la detección.
3.
Solo se lee el cuerpo previamente analizado: el flujo de la petición no se consume directamente. Se omiten flujos binarios y multipartes.
4.
Campos personalizados con extra_sensitive_keys. Si su aplicación utiliza nombres propios como account_number o medical_record_number, especifíquelos para recibir el mismo tratamiento estricto de redacción.
init_app(app,
    api_key=os.environ["CYBAT_API_KEY"],
    gcp_project_id="my-gcp-project",
    capture_body=True,
    extra_sensitive_keys={"account_number", "medical_record_number", "internal_employee_id"},
)
