Middleware for Flask, Django, FastAPI and any ASGI app that reports HTTP traffic directly to the Cybat Intelligence Engine.

Quick Start_

Four steps from an empty terminal to live detection.

1.

Install the package

pip install cybat-sdk
2.

Create an API key

From the Intelligence Portal → API Keys. It's shown once — store it as CYBAT_API_KEY, it can't be retrieved again.

3.

Add the middleware

One import, one call — see Code Samples below for your framework.

4.

Generate traffic, watch the dashboard

Requests appear in the Intelligence Portal within seconds — app listed as Connected, Threat Globe populating, incidents in the feed.

Installation_

pip install cybat-sdk

Supported Python versions

3.9, 3.10, 3.11, 3.12, 3.13

Dependencies

None at runtime — the SDK uses only urllib from the standard library for its HTTP call.

Code Samples_

All three integrations take the same options — see Configuration Reference for the full list.

Flask

WSGI 
from flask import Flask
from cybat_sdk.integrations.flask import init_app

app = Flask(__name__)
init_app(app,
    api_key=os.environ["CYBAT_API_KEY"],
    gcp_project_id="my-gcp-project",  # required (or aws_project_id) -- also enables automatic blocking
    service_name="checkout-api",      # optional, just a label on incidents
)

Django

WSGI middleware 
# settings.py
MIDDLEWARE = [
    # ... your other middleware ...
    "cybat_sdk.integrations.django.CybatMiddleware",
]
CYBAT_API_KEY = os.environ["CYBAT_API_KEY"]
CYBAT_GCP_PROJECT_ID = "my-gcp-project"  # required (or CYBAT_AWS_PROJECT_ID) -- also enables automatic blocking

Every option has a CYBAT_* settings equivalent — the Django setting name is CYBAT_ + the option name upper-cased.

FastAPI / Starlette

ASGI 
from cybat_sdk.integrations.asgi import CybatASGIMiddleware

app.add_middleware(CybatASGIMiddleware,
    api_key=os.environ["CYBAT_API_KEY"],
    gcp_project_id="my-gcp-project",
)

Speaks the raw ASGI protocol directly (not a framework-specific base class), so streaming responses work correctly. For a bare ASGI app without add_middleware: app = CybatASGIMiddleware(app, api_key=...).

Behind a load balancer or reverse proxy?

Configure your framework's standard mechanism for trusting X-Forwarded-For (e.g. Werkzeug's ProxyFix for Flask) — otherwise every request reports your proxy's IP instead of the real client's, and Cybat won't be able to tell your traffic apart.

Multi-Cloud Routing_

Set exactly one of gcp_project_id or aws_project_id — required, and never both on the same SDK instance. Whichever you set decides where data is sent, automatically.

You set Data goes to Status
gcp_project_id gcp-ingest.cybat.co Live
aws_project_id aws-ingest.cybat.co Not yet implemented

An app that runs in both clouds needs two SDK instances, one per cloud — not one instance with both fields set (the constructor raises if you do that). It also raises if neither is set.

Configuration Reference_

Flask and ASGI take these as keyword arguments; Django reads them from settings.py as CYBAT_*.

Option Default Description
api_key — Required. Raw key from the Intelligence Portal.
gcp_project_id — Required unless aws_project_id set. Routes to GCP, enables automatic blocking.
aws_project_id — Required unless gcp_project_id set. Routes to AWS — not yet live.
service_name None Optional label shown on incidents.
ingest_url auto Overrides cloud auto-detection — for local/staging testing.
flush_interval_ms 2000 How often a partial batch is flushed.
max_batch_size 100 Flushes immediately once the buffer reaches this size.
max_retries 2 Retries before a failed batch is dropped (3 attempts total).
retry_backoff_ms 500 Base delay before the first retry; doubles each retry.
status_filter "all" "all" | "errors" | a callable (status: int) -> bool.
capture_body False Send a redacted excerpt of the request body — see below.
body_max_bytes 2048 Cap on the body excerpt after redaction (max 8192).
body_status_filter "all" Capture bodies only for matching responses, independent of status_filter.
extra_sensitive_keys None Extra field names redacted like the built-in list (exact, case-insensitive match) — e.g. {"account_number"}. See Request Bodies & Redaction.

Request Bodies & Redaction_

capture_body is off by default. Bodies are where injection attacks, credential stuffing and prompt-injection against LLM-backed endpoints actually show up, so enabling it materially improves detection — and it means request content leaves your infrastructure. Four things worth knowing before you turn it on:

1.
Redaction is not optional once this is on. Before an event is even buffered, the body is masked in-process — emails, card numbers (Luhn-checked), JWT/Bearer tokens, provider API keys, and the value of any field named like a secret (password, token, cvv, ssn…).
2.
A masked secret keeps its attack shape, not its content. It's replaced by a content-free descriptor such as [REDACTED len=13 sus=quote,comment] — its length and what kind of attack characters it contained, so a SQL injection typed into a password box is still visible to detection, but the value is not.
3.
Only the already-parsed body is read — the request stream is never consumed directly, so your body-parsing middleware must run first. JSON, form-encoded and text bodies only; multipart and binary are skipped. Bodies are capped (default 2 KiB, hard max 8 KiB).
4.
Your own field names can be added with extra_sensitive_keys. The built-in list can't know that account_number or medical_record_number is sensitive in your app — pass a set of your own field names and they get the same content-free treatment as the built-in ones. Matching is an exact, case-insensitive field name, never a substring, so a short name you add can't accidentally swallow unrelated keys.
init_app(app,
    api_key=os.environ["CYBAT_API_KEY"],
    gcp_project_id="my-gcp-project",
    capture_body=True,
    extra_sensitive_keys={"account_number", "medical_record_number", "internal_employee_id"},
)
